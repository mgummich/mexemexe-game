# 05 — Invalid Table / Mistake Recovery

Goal: make experimentation feel safe; a broken table should feel solvable, not punitive.

- **RECOVERY-01** Use three conceptual states: valid, unresolved/in-progress, true problem.
- **RECOVERY-02** Avoid generic error language for normal intermediate states.
- **RECOVERY-03** When FEITO cannot complete, point directly to the blocking meld/card(s).
- **RECOVERY-04** Show missing run cards spatially and pulse duplicate/conflicting cards directly.
- **RECOVERY-05** Make invalid FEITO act like `check my work`: valid areas recede, problem stays emphasized, concise explanation appears.
- **RECOVERY-06** Use gentle rejection shake/sound, not harsh system-error feedback.
- **RECOVERY-07** Let Undo briefly become more discoverable after a table-breaking edit; do not pulse indefinitely.
- **RECOVERY-08** Animate multi-step Undo consistently and preserve spatial memory.
- **RECOVERY-09** Consider clearer Reset wording such as `RECOMEÇAR JOGADA`; confirm only for large drafts.
- **RECOVERY-10** Do not interrupt experimentation with modal errors.
- **RECOVERY-11** In guided mode, show problem count progressing toward zero and `MESA PRONTA ✓` when solved.
- **RECOVERY-12** Detect prolonged unresolved hesitation and progressively surface help.
- **RECOVERY-13** Add a `show problem` interaction that cycles through unresolved areas where useful.
- **RECOVERY-14** Make joker failures expose the joker's interpreted role.
- **RECOVERY-15** Animate impossible drops back to origin so the player can perceive registration and rejection.
- **RECOVERY-16** Keep important rule explanations visible until changed or long enough to read.
- **RECOVERY-17** Consider an optional `VER ORIGINAL` ghost/reference for complex drafts if it fits existing editor architecture.

Verification: duplicate-suit set, broken run, joker error, invalid FEITO, undo chain, reset small/large, stuck-help timing, reduced motion.
